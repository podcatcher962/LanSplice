### 1. 小众软件 · 发现频道（最优先）

标题：

```
LanSplice - 两台电脑之间直接传文件，不经过网盘，Windows / 信创 / macOS
```

正文：

```
一个局域网直传工具，自己写的，MIT 开源。

用途很朴素：两台电脑在同一个路由器下，把文件或整个文件夹直接推到对方硬盘。
不开 Windows 共享、不装网盘、不插 U 盘。

Windows 就一个 exe，13 MB，双击就跑，不用装 Python。
Linux 那边给了离线安装包（带 4 个 wheel），断网、没有 pip 的机器也能装 —— 这点是在
统信 UOS 20 真机上试出来的，44 项自检全过。

几个自己用得上才做的功能：
· 传一半断了能接着传，不从头来
· 对端已有同名文件不覆盖，不会悄悄替换掉
· 剪贴板里的文字一键推到对面
· 手机扫码用浏览器就能收发
· 关窗口只是缩到托盘，接收不中断
· 两台目录可以一键镜像
· 没有服务器也能几台机器内网群聊（配对码当房间口令）

千兆网线实测 87 MB/s，全程 AES-256，文件点对点，不经过任何第三方服务器。

下载：https://github.com/podcatcher962/LanSplice/releases/latest
（Windows exe、Linux/信创 tar.gz 都在同一个 release 里）

界面中英双语，首页右上角切换。
```

### 2. LINUX DO

标题：

```
自己写的局域网直传工具，在没 pip、断网的 UOS 20 上装起来了
```

正文：

```
先说为什么做：两台机器之间搬一个 8.9 GB 的音频包，U 盘要来回走，网盘白绕一圈外网。

于是写了个局域网直传。Windows 一个 exe，Linux 一侧当时是最大的坎 ——
统信 UOS 20 那台机器，python3 是 3.7.3，没有 pip，apt 源也连不上，
装 cryptography 直接卡死。

最后的做法：安装包里直接塞 4 个离线 wheel（cp37 / x86_64），
install.sh 先试着装现成的 python3-cryptography，装不上就用本地 wheel，
全程不需要网络。装完自带一个 --check 做 44 项自检，0 失败 0 跳过，13.7 秒跑完。

顺手踩过、记下来的坑：
· 中文字体不能硬写「微软雅黑」，要按 Noto Sans CJK → 思源黑体 → 文泉驿 → Droid 挨个试，
  不然中文全是方框
· 网卡枚举不能靠 gethostbyname_ex(hostname)，Linux 上主机名通常只映射到 127.0.1.1，
  多网卡（docker0 / virbr0 / VPN）永远发现不到对端。改成 ioctl 拿 SIOCGIFADDR 自己算广播地址
· 单实例锁从文件锁换成 fcntl.flock，进程一死内核自动释放，不会留「上次没退干净」的死锁文件
· 防火墙不替你改，只按本机装的是 ufw / firewalld / iptables 挑一条命令给你复制

现在 Windows / Linux / macOS 走同一个协议，可以互传，也能在局域网里群聊（无服务器）。

MIT 开源，13 MB 单文件，不需要装 Python。
https://github.com/podcatcher962/LanSplice

（macOS 那条线要说清楚：代码和打包脚本都写好了，但手上没有 Mac 真机，
界面还没在真机上跑过。文档里逐条标了哪些有证据、哪些没有。）
```

### 3. V2EX · 分享创造

标题：

```
[分享] 写了个局域网直传工具，两天 26 个版本，最后一个 bug 挺有意思
```

正文：

```
起因很土：两台机器之间搬一个 8.9 GB 的包。

做完之后最值得记的不是功能，是最后那个 bug。

v1.7.3 把 Windows 防火墙规则从「按 exe 路径建」改成「按端口建」——
因为按路径建的话，每换一个版本号 exe 路径就变一次，用户每次升级都要重新放行一次，
这事被骂了很久。

改完第二天，用户说：一键放行点了十几次，灯还是红的。

查下来是：规则改成按端口了，但**读这个规则的地方忘了改**。
读的那段还在拿 `Program` 字段跟当前 exe 路径比，而按端口的规则那里写的是 `Any`。
`os.path.abspath("Any")` 得到的是一个叫 Any 的路径（在当前工作目录下），
永远不可能等于真实 exe。于是灯恒红，点多少次都没用。

更有意思的是另一台机器看着是绿的。查了半天，是它上面留着 Windows 弹窗时
自动建的旧规则，那条恰好满足旧判据。纯属巧合 —— 两台机器两个假象，
一个是假红，一个是假绿。

教训：改机制的时候，读这个机制的地方要一起改。测试也是，状态灯和「放行后自查」
如果不共用同一套判据，就会出现「说成功了其实没成功」。

技术栈很无聊：Python + tkinter + PyInstaller，AES-256-GCM 分块加密，UDP 广播发现。
值得说的是发现那块：广播不能只发 255.255.255.255，Windows 会按路由度量挑一块网卡，
装了 VMware / Hyper-V / VPN 的机器经常挑中虚拟网卡，广播进了虚拟网段，
真实局域网上的对端永远收不到。要对每块网卡的子网广播地址各发一遍。

现在是 Windows / Linux（统信 UOS、麒麟）/ macOS 三端，一个协议。
UOS 20 真机 44 项自检 0 失败。935 项自动化测试。

MIT，没广告没内购没会员。
https://github.com/podcatcher962/LanSplice

（macOS 那条线坦白说：没有真机，界面还没跑过，文档里标了。）
```
