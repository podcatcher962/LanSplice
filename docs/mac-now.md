# MacBook 现在怎么用 LanSplice

> 适用版本：v1.5.2（2026-11-01）
> 一句话：**Mac 上不用装任何东西 —— 用浏览器打开一个地址就行。**

---

## 一、五分钟走完（推荐，零安装）

### 1. 两台机器连同一个 Wi-Fi

同一个路由器、同一个网段。手机热点也行（那就是两台都连这个热点）。

⚠️ 公司/酒店的 Wi-Fi 常开「AP 隔离」（客户端之间互不可见），这种网络下再怎么试都不通，换手机热点验证一下就知道是不是这个原因。

### 2. 在 Windows 上打开「手机传文件」

Windows 上的 LanSplice → 菜单 **文件 → 手机传文件…**

会弹出一个窗口：上面是二维码，中间是地址，长这样：

```
http://192.168.1.20:47822/?t=3f9c1a7e5b2d4c8e9a0b1c2d
```

### 3. 在 Mac 上打开这个地址

先点窗口里的 **「复制」** 按钮（地址栏下方那一排，点完会变成「已复制」），
把地址发到 Mac 上（微信/备忘录都行），再用 Safari 或 Chrome 打开。

> 二维码是给手机扫的，Mac 没有扫码这一步 —— 用中间那个地址。
> 地址很长，别手打，一定要点「复制」。

### 4. 收发

| 在 Mac 上要做的事 | 怎么做 |
|---|---|
| **把文件发给 Windows** | 点「选择文件发送」，或**直接把文件拖进虚线框**。进度条在下面，传完显示「已保存」 |
| **从 Windows 拿文件** | 下半部分「电脑上的文件」列出接收目录的内容，点右侧「下载」，存进 Mac 的「下载」文件夹 |
| **看不到最新文件** | 点「刷新列表」 |

支持多选、支持拖多个文件（会排队逐个传）。

### 5. 用完就关

在 Windows 上关掉那个窗口，服务立刻停 —— 它只在窗口开着时监听，不是常驻。

## 二、现在能做到什么、做不到什么

| | 状态 | 说明 |
|---|---|---|
| Mac → Windows 传文件 | ✅ 可以 | 走浏览器上传，单个文件上限 8 GB |
| Windows → Mac 拿文件 | ✅ 可以 | 列出 Windows 接收目录，点「下载」 |
| 同名自动改名不覆盖 | ✅ 可以 | 存成 `xxx (2).ext` |
| 断点续传 | ❌ 不行 | 浏览器上传中断就得重来。这是协议层的能力，网页端用不到 |
| 文件夹镜像 | ❌ 不行 | 要客户端 |
| 从 Mac 主动「选设备」扫描 | ❌ 不行 | 网页端是被动接收方，由 Windows 发起 |
| 传文件夹（整个目录） | ⚠️ 部分 | 浏览器只能逐个文件选，不能传目录树 |

**一句话概括**：临时互传文件够用；大文件、断点续传、目录同步，得等 Mac 客户端。

## 三、打不开？按这个顺序排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 转圈超时 / 打不开 | **Windows 防火墙拦了 47822** | Windows 第一次弹「是否允许访问」时勾**专用网络**。没弹或点过「取消」：控制面板 → Windows Defender 防火墙 → 允许应用通过 → 找到 LanSplice 打勾（专用+公用） |
| 同上 | 两台不在同一网段 | `ipconfig`（Win）看 IPv4 是不是 `192.168.1.x` 这种；Mac 上「系统设置 → Wi-Fi → 详细信息」看 IP 前三位是否一致 |
| 打开是「需要扫码进入」 | 地址里的 `?t=...` 口令缺失或过期 | 回 Windows 窗口点「刷新二维码」，用新地址。旧口令在窗口关掉后就失效 |
| 页面能开，但列表空、上传失败 | 连到了虚拟网卡 | 机器上装了 VMware / VirtualBox / Hyper-V / VPN 时，地址里的 IP 可能挑中虚拟网卡。用 `ipconfig` 找**物理 Wi-Fi 那块**的 IPv4，把地址里的 IP 换成它 |
| 一直 403 | 不是内网来源 | 说明你访问时经过了公网/代理（比如开了系统代理、或用公司 VPN 全局模式）。关掉代理再试 |

## 四、想更顺手：Mac 上直接跑源码（只能发，不能收）

原理：LanSplice 的传输协议没用任何 Windows API，Mac 上能跑起来。但图形界面用到了 Win32（托盘、注册表），**Mac 上起不来**，只能跑命令行。

```bash
# 1) 装依赖（macOS 自带 python3，cryptography 要单独装）
python3 -m venv ~/.l2p && source ~/.l2p/bin/activate
pip install cryptography

# 2) 进到源码目录（从 GitHub 下 zip 解开即可）
cd ~/Downloads/LanSplice-1.5.2

# 3) 看版本，确认能跑
python3 link2pc_cli.py version

# 4) 发给 Windows（配对码在 Windows 端的连接面板里，形如 ABCD-EFGH-JKLM-NPQR）
python3 link2pc_cli.py send ~/Movies/demo.mp4 --to 192.168.1.20 --code ABCD-EFGH-JKLM-NPQR

# 5) 扫描局域网里的设备（UDP 广播，可能要等 1.5 秒）
python3 link2pc_cli.py devices
```

前提：Windows 那台**开着 LanSplice**（服务端在跑），否则连不上。

> 这条路我没法实测 —— 手上只有 Windows。协议层是纯标准库 + cryptography，理论上通；真要用请先拿一个小文件试，别一上手就传 8 GB。
> 另外命令行**没有「接收」子命令**，Mac 收文件还是得走上面的浏览器方案。

## 五、Mac 客户端什么时候有

| 阶段 | 内容 | 预计 |
|---|---|---|
| v1.6.0 / v1.6.1 | 单实例、防火墙换版本重放行、传输历史、镜像收藏 | 11/1–11/2 |
| 平台层 | 把自启 / 打开目录 / 防火墙 / 托盘抽出来 | 11/3–11/4 |
| Linux 命令行 + 界面 | 信创线先跑通 | 11/5–11/9 |
| **Mac 客户端** | `.app`（未签名，首次要右键「打开」） | **11/8–11/10** |

Mac 版要多处理四件 Windows 没有的事：托盘重写、LaunchAgents 自启、Gatekeeper 签名、macOS 14+ 的「本地网络」权限（不给就扫不到任何设备）。

## 附：转给别人的三行版

> Mac 不用装东西：Windows 上开「文件 → 手机传文件」，把窗口里那行 `http://192.168.x.x:47822/?t=...` 地址复制到 Mac 的浏览器打开，就能收发。
> 同一 Wi-Fi，Windows 防火墙第一次要允许「专用网络」。
> 断点续传和目录镜像要等 Mac 客户端，预计 11 月上旬。
